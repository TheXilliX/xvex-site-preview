# X.Vex · сайт

Адаптивная главная, возможности, скачивание, справка и локальный предпросмотр аккаунта.

## Запуск

Нужен Node.js 24 или новее.

```sh
npm run dev
npm test
```

Откройте http://127.0.0.1:4179. Кнопка на главной ведёт на страницу платформ. Для Windows сайт получает установщик из последнего релиза `TheXilliX/xvex-updates`. Кнопка сразу направляет на файл установщика из манифеста обновлений.

## Локальная проверка аккаунта

Запустите X.Vex из исходников и откройте «Настройки → Аккаунт» или «Хранилища → Подключить к синхронизации». Можно войти с аккаунтом сайта или создать аккаунт прямо в приложении. Оба входа используют одну базу. Сессия приложения живёт в памяти до выхода или перезапуска. Веб-сессия хранится в HttpOnly cookie. База тестовых данных находится в `.data/` и игнорируется Git.

Сервер предпросмотра слушает только 127.0.0.1. Для релизной сборки приложение принимает адрес HTTPS-сервера аккаунтов через `VITE_XVEX_ACCOUNT_ORIGIN` при сборке. Для публичного запуска потребуется HTTPS-сервер с постоянной базой и подключение сервиса отправки писем.

### Подтверждение почты и восстановление пароля

Локальные тестовые письма сохраняются в `.data/mail/`. При необходимости каталог можно задать через `XVEX_MAIL_OUTBOX`. Файлы содержат одноразовые ссылки, открывайте их в браузере на компьютере с запущенным сервером.

1. Зарегистрируйте тестовый аккаунт или запросите новую ссылку в профиле. Откройте письмо подтверждения и нажмите «Подтвердить почту».
2. На странице входа нажмите «Забыли пароль?» и укажите подтверждённую почту. Откройте письмо сброса и задайте новый пароль.

Ссылка подтверждения действует 24 часа, ссылка сброса — 30 минут. Сброс завершает прежние сессии сайта и приложения. В локальной версии вход доступен до подтверждения почты.

## Админ-панель

Создайте свой тестовый аккаунт и выдайте ему роль из каталога сайта. Укажите адрес аккаунта, к которому у вас есть доступ. Почта в локальном предпросмотре не подтверждается.

```sh
npm run admin:grant -- owner@example.com
```

Войдите заново и откройте «Админ-панель» рядом с логотипом X.Vex или страницу `/admin`. Команда завершает текущие сессии этого аккаунта на сайте и в приложении. При заданном `XVEX_DATABASE` запускайте команду с той же базой, что и сервер.

Администратор может найти аккаунт по почте или имени и выдать или отозвать доступ к X.Vex Sync. Статус сохраняется в базе и виден в профиле. Это ручной доступ. В тестовой сборке материалы синхронизируются вручную. Оплата подписки ещё не подключена.

## Проверка X.Vex Sync

В приложении войдите в аккаунт сайта. Выдайте аккаунту доступ к Sync в админ-панели. В «Настройки → Синхронизация» укажите имя облачного хранилища и синхронизируйте устройство с материалами. На втором устройстве откройте пустое локальное хранилище, войдите в тот же аккаунт и укажите то же имя. Изменения передаются при нажатии «Синхронизировать». Если обе стороны изменились, приложение оставит обе версии.

Для теста Android подключите устройство или эмулятор через ADB и выполните `adb reverse tcp:4179 tcp:4179`. Соберите отладочное приложение с `VITE_XVEX_LOCAL_ACCOUNT_PREVIEW=1`. Внешние вложения и настройки хранилища в тестовый обмен не входят. Используйте отдельную тестовую папку.

Для теста через HTTPS задайте `XVEX_PUBLIC_ORIGIN` с адресом навигации сайта и направьте HTTPS-прокси на локальный порт сервера. Для сборки приложения укажите тот же адрес в `VITE_XVEX_ACCOUNT_ORIGIN`. Для такого теста создайте отдельную базу через `XVEX_DATABASE` и отдельную папку писем через `XVEX_MAIL_OUTBOX`. Сборка с HTTPS-адресом подключается и на физическом Android без ADB.
